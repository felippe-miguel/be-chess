# react-chessboard API notes (scaffolding reference)

These notes were generated by reading the actually-installed package, not assumed from
memory or older docs. Re-verify if the dependency is ever bumped.

## Exported component

The package exports a single board component, `Chessboard`, from the package root
(`react-chessboard`), re-exported via `dist/index.d.ts` → `./Chessboard.js`:

```ts
import { Chessboard } from 'react-chessboard';
```

It also exports `ChessboardProvider`, `useChessboardContext`, `SparePiece`, plus
assorted type/util/default exports (`Arrow`, `SquareDataType`, `PieceDataType`,
`DraggingPieceDataType`, `PositionDataType`, `SquareHandlerArgs`, `PieceHandlerArgs`,
`PieceDropHandlerArgs`, `SquareRenderer`, `PieceRenderObject`, `FenPieceString`,
`ChessboardOptions`, etc.).

## `Chessboard` component signature

Confirmed from `dist/Chessboard.d.ts`:

```ts
type ChessboardProps = {
  options?: ChessboardOptions;
};
export declare function Chessboard({ options }: ChessboardProps): JSX.Element;
```

**This confirms the v5 API change mentioned in the task: there is exactly one prop,
`options`, which is a single config object — there are no individual top-level props
like `position`, `boardWidth`, `onPieceDrop`, etc. (those all now live _inside_
`options`).**

Notable points for whoever wires up the board next:

- `position` accepts **either** a FEN string **or** a `PositionDataType`
  (`{ [square: string]: PieceDataType }`, where `PieceDataType = { pieceType: string }`).
  There is no `fen` prop — pass the FEN string straight into `options.position`.
- Move handling is via `onPieceDrop`, which must return a `boolean` (presumably to
  signal whether the drop was accepted/should animate). Its argument shape is
  `PieceDropHandlerArgs = { piece: DraggingPieceDataType; sourceSquare: string;
targetSquare: string | null }`, not the old `(sourceSquare, targetSquare, piece)`
  positional-args signature from v4 and earlier.
- There is no `boardWidth` prop; sizing instead comes from `chessboardRows` /
  `chessboardColumns` plus CSS (`boardStyle`, `squareStyle`, etc.) — board width is
  controlled by styling the container/board, not a dedicated numeric prop.
- `Chessboard` internally wraps `ChessboardProvider`/context (`useChessboardContext`),
  but consumers normally just render `<Chessboard options={...} />` directly; the
  provider/hook are exported for advanced custom-piece/custom-square use cases.
